# Корректировка остатка сырья

Статус: `Completed`.

## Цель

Дать Директору и администратору безопасно уменьшать ошибочный или тестовый остаток сырья отдельной аудируемой операцией, не удаляя исходные приходы и не подменяя историю.

## Scope

- отдельный тип операции корректировки сырья;
- транзакционное уменьшение остатка без ухода в минус;
- обязательная причина и snapshot остатка до/после;
- право `operation.correct` на API и действие только в директорском интерфейсе;
- вход `Еще → Цех → Сырье → Скорректировать`;
- обновление остатков, сводки, аналитики текущего остатка и общей истории после операции.

## Out of scope

- корректировка тары, готовой продукции, распределителя, курьера и денег;
- увеличение остатка через корректировку;
- удаление или редактирование исходного прихода;
- автоматическое удаление тестовых данных из production БД;
- отдельный раздел корректировок.

## Тестовый план

- happy path: баланс уменьшается, correction fact, operation и audit создаются;
- запрет нулевого/отрицательного количества и короткой причины;
- запрет списания сверх остатка и отсутствие частичной записи;
- проверка права `operation.correct`;
- UI доступен Директору и отсутствует у заведующего производством;
- UI обновляет остатки после успеха;
- lint, typecheck, unit/integration tests, build, docs-check, React Doctor.

## Риски и rollback

- Риск: конкурентные списания уводят остаток в минус. Защита: conditional decrement внутри транзакции и DB check `quantity >= 0`.
- Риск: корректировку используют вместо реального производственного расхода. Защита: обязательная причина, отдельный тип операции и доступ только по `operation.correct`.
- Rollback кода: убрать UI/endpoint после остановки использования. Миграцию после появления production-фактов не откатывать удалением таблицы; новые записи остаются частью истории.

## Открытые вопросы

Нет. Корректировка уменьшает остаток на указанное количество; увеличение выполняется только обычным приходом.

## Результат

- Добавлена append-only корректировка сырья с отдельным typed fact, operation и audit.
- Остаток уменьшается условным обновлением внутри transaction и защищен DB constraint от отрицательного значения.
- API доступен только по `operation.correct`; в web действие показано Директору и скрыто от заведующего производством.
- Положительный остаток архивного вида сырья остается видимым до корректировки, нулевой исчезает из рабочих списков и текущей аналитики.
- Миграция `20260903143000_raw_material_correction` применена к локальной dev БД.
